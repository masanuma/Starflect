# 毎日の楽しみと特別便

追加の公開前確認：[7言語の検証・修正記録](LANGUAGE-QA.md)。49ケースの生成と保存・エラーの回帰確認を実施。本番未反映。

2026-09-09。「①楽しみの予告＋②キャラの一言を毎日の入口にし、③特別便を時折の変化として加える」を実装。④日記は採用しない。

## 毎日の入口

- 日次v2に任意の `greeting` を追加。新規生成ではキャラが届ける小さな楽しみを短く書き、吹き出しとして見出しを置き換える。headlineは共有用に保持。
- キャラの背景色と傾きを計算済みの星もように合わせる。既存の顔なしSVGを使い、表情の追加や強いアニメーションは行わない。
- 本文は吹き出しを反復せず短くする編集指示。夜・注意日は安心や本人が選べる楽しみを描き、出来事の成功を保証しない。
- 古いJSONとプレーンテキストはそのまま読める。保存済み運勢は引き直さず、新規生成から吹き出しが付く。相談にも吹き出しを含む自然文を渡す。

## 特別便

- 端末の天体暦で、運行する金星・木星と出生の太陽・月・金星の60度／120度を計算する。
- 毎日の正午サンプルでずれ0.6度以内、前後の日より近い局所的な最小点を候補にする。正確な時刻の予言ではなく「その日ごろ」と表示。
- 各暦月の最初の候補を選び、同日の候補はずれの小さい順。月最大1通、該当がない月はなし。月全体を固定して選ぶため、再訪時に別の便へ差し替わらない。
- 選んだ日の前後3日以内にアプリを開くと届く。月境界も前後の月を調べる。未訪問期間の便を全部配る仕組みではない。
- 届いた便は未開封でも端末に保存し、期間後は「届いた特別便」で読める。本人の既存データ引き継ぎに含まれる。人物変更時は混在させない。
- AI生成は封筒を開いたときだけ。人物・便・言語ごとの生成済み本文は上書きしない。失敗は再試行でき、本文のない便も残す。
- 根拠は折り畳み、通常の表示は楽しみと時期を主役にする。日次の総合運が良いと保証するものではない。

## 確認と制限

- 型チェック、本番ビルド、既存の日次／週次回帰テスト。
- `scripts/verify-delight.ts`：実天体暦の月境界の節目、候補なし、配達重複防止、後日の保持、本文の上書き防止、言語・人物分離、旧形式との互換性。
- ローカル実APIで昼・夜・英語のgreetingと特別便を生成。初回の抽象的な文章と英語への日本語混在を踏まえ、具体性・翻訳指示を修正して再確認。
- `live-delight-check.json` は架空人物の実生成例。特別便は同じ人物の2026年1月13日の計算結果を使う。プレビューでは現在日付に関係なく表示確認のため並べる。
- ブラウザで390px／320px幅、注意日の吹き出し、封筒の開閉と本文を確認。
- 生成の文章量・具体性にはまだばらつきがあるため、日々の利用で読み味は継続確認する。

ローカル確認：`/delight-preview.html`（生成例・既存データへの変更なし）、`/app?lang=ja`（実際の利用）。プレビューは本番ビルドの入口に含めない。今回の追加機能は本番未反映。
